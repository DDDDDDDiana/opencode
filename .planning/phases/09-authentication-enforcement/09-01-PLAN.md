2. **中间件逻辑** (在第130行`.use(cors(...))` 之后插入):

```typescript
.use(async (c, next) => {
  // 豁免路由列表
  const exempt = ["/health", "/metrics", "/ready", "/log", "/doc"]
  if (exempt.some(path => c.req.path.startsWith(path))) {
    return next()
  }

  // 读取API key并验证
  const key = c.req.header("x-opencode-api-key")
  const identity = await resolve(key)

  // 认证失败返回401
  if (identity.state === "anonymous") {
    return c.json(
      { error: "Unauthorized", message: "Valid API key required" },
      {
        status: 401,
        headers: { "WWW-Authenticate": 'Bearer realm="opencode"' }
      }
    )
  }

  // 认证成功，设置UserContext并继续
  return UserContext.provide(identity, () => next())
})
```

**关键点:**

- 中间件在CORS之后执行，确保CORS headers已设置
- 中间件在Admin basicAuth之后执行，两套认证独立运作
- 豁免路由使用`startsWith`匹配，支持子路径(如`/doc/openapi.json`)
- 401响应包含`WWW-Authenticate` header符合HTTP规范
- 使用`UserContext.provide()`包装`next()`确保身份传播到后续中间件和路由
